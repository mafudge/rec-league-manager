# Deploying the live site

**What this is.** The runbook for the live site: one copy of the app, built from `main`, so it always shows the newest release. Shipping a release is merging its release branch to `main`; both hosts redeploy on their own. Why it's done this way: [ADR 006](decisions/006-deploy-from-main.md), which replaced the one-site-per-release plan in [ADR 005](decisions/005-free-tier-deployment.md). To see an older release, check out its tag (`git checkout v0.2.0`) and run it locally ([`src/README.md`](../src/README.md)).

**What gets deployed.** FastAPI + web, nothing else. The other eleven pairings run locally.

| Piece | Host | Address | Built from |
|---|---|---|---|
| API | Render Free web service | `https://rlm-api-v0-2-1.onrender.com` | `render.yaml` on `main` |
| Web | Vercel Hobby project | your Vercel project's `*.vercel.app` URL | `src/frontends/web` on `main` |

The `v0-2-1` in the API's name is where the service started, not the version it runs. Renaming it would make a new service at a new URL, so it stays.

**What a visitor should know** (also in the root README):
- The first visit after 15 quiet minutes takes up to a minute while the free API wakes up.
- Creating an account needs the sign-up password, which the site's owner shares. The demo sign-in below needs nothing.
- Anything a visitor adds disappears when the API sleeps, and every night. Every start brings back the demo: `demo@recleague.example` / `cornhole-demo`, "Tuesday Cornhole", public link `/l/tuesdy`.

## One-time setup

You need a Render account and a Vercel account, each signed in with GitHub and given access to this repository. Neither asks for a card on the free plan. There's no domain, server or database to look after.

### 1 · API on Render
1. Render dashboard → **New → Blueprint** → pick this repository and branch **`main`**. Render reads `render.yaml` and proposes one free web service, `rlm-api-v0-2-1`. Apply it.
   - Already have the service from a release branch? Service → **Settings → Build & Deploy → Branch** = `main`. Nothing else changes.
2. Service → **Environment** → set `SIGNUP_PASSWORD` (Render asks for it because `render.yaml` marks it `sync: false`). Pick something students can't guess, and give it only to people who should be able to create an account. Without it, sign-up is closed and the demo seed can't start, so the deploy fails.
3. Wait for the first deploy to pass its health check (`/api/health`). The deploy log should show `Demo seed done`.
4. Check it from this machine: `SIGNUP_PASSWORD=<the one you set> src/contract-test.sh https://rlm-api-v0-2-1.onrender.com` should print `contract ok`. The contract test signs up its own throwaway accounts, and the next reset removes them.
5. Service → **Settings → Deploy Hook** → copy the URL. GitHub → repository **Settings → Secrets and variables → Actions → New secret** named `RENDER_HOOK`.

`JWT_SECRET` is generated by Render for the service, so it is never in the repo.

### 2 · Web on Vercel
1. Vercel dashboard → **Add New → Project** → import this repository.
2. Root directory `src/frontends/web`. Framework preset Next.js, detected automatically.
3. Environment variable `NEXT_PUBLIC_API_URL` = `https://rlm-api-v0-2-1.onrender.com`, with no trailing slash. It is baked in at build time, so changing it later needs a redeploy.
4. **Settings → Git → Production Branch** = `main` (Vercel's default), and **Settings → General → Node.js Version** = 22.x. Vercel no longer builds on 18, and Next.js 15 runs on 22. Redeploy once so both settings apply.
5. Open the Vercel URL on a phone: sign in as the demo organizer, then open `/l/tuesdy` signed out.

Vercel also builds a preview for every other branch you push (release and `dev/` branches). Those are fine to ignore; only `main` is the live site.

### 3 · Nightly reset
`.github/workflows/nightly-reset.yml` redeploys the API at 08:00 UTC using the `RENDER_HOOK` secret. GitHub only runs scheduled workflows from `main`. To reset now, use **Actions → Nightly demo reset → Run workflow**. If the secret is missing, the run shows a warning instead of failing.

## Shipping a release

1. When every issue in the release is closed, merge `release/vX.Y.Z` to `main` with `--no-ff` and push. Render and Vercel both redeploy from `main`.
2. Wait for both deploys, then run `SIGNUP_PASSWORD=… src/contract-test.sh https://rlm-api-v0-2-1.onrender.com` and open the web URL on a phone (demo sign-in, `/l/tuesdy` signed out).
3. Tag the merge `vX.Y.Z` and push the tag.
4. Update the root `README.md` if anything a visitor needs to know changed.

The previous release is replaced, not kept. Its tag is how anyone gets it back.

## When something goes wrong

| Symptom | Likely cause |
|---|---|
| Web says "Can't reach the backend at …" | `NEXT_PUBLIC_API_URL` is wrong or has a trailing slash. Fix it and redeploy the Vercel project. |
| First request hangs for about 50 s | That's normal: the free API was asleep. |
| Render deploy fails at start with `Seed refused at …` | A route refused the seed's data. The previous deploy keeps serving. Fix the seed on a dev branch. |
| A merge to `main` broke the live site | Revert the merge commit on `main` and push; both hosts redeploy the previous code. Or use Render's and Vercel's **Rollback** to the last good deploy while you fix it. |
| Render deploy fails with `Seed refused at POST /api/auth/signup: 403 … Sign-up is closed` | `SIGNUP_PASSWORD` isn't set on the service. Set it under Environment; Render redeploys. |
| Demo data didn't reset overnight | The `RENDER_HOOK` secret is missing, which shows as a warning in the workflow run. Or GitHub paused scheduled workflows after 60 days without a commit: re-enable it under Actions. |
