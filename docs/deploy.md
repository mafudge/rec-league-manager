# Deploying a release

**What this is.** The runbook for REL-01: every release goes online at its own pair of free addresses and stays there after the next release ships, so students can compare v0.2.1 with v0.3.0 and later releases. Why it's done this way: [ADR 005](decisions/005-free-tier-deployment.md).

**What gets deployed.** FastAPI + web, nothing else. The other eleven pairings run locally ([`src/README.md`](../src/README.md)).

| Piece | Host | Address (v0.2.1 shown) | Built from |
|---|---|---|---|
| API | Render Free web service | `https://rlm-api-v0-2-1.onrender.com` | `render.yaml` on the release branch |
| Web | Vercel Hobby project | `https://rlm-v0-2-1.vercel.app` | `src/frontends/web` on the release branch |

**What a visitor should know** (also in the root README):
- The first visit after 15 quiet minutes takes up to a minute while the free API wakes up.
- Anything a visitor adds disappears when the API sleeps, and every night. Every start brings back the demo: `demo@recleague.example` / `cornhole-demo`, "Tuesday Cornhole", public link `/l/tuesdy`.

## One-time setup

- A Render account and a Vercel account, each signed in with GitHub and given access to this repository. Neither asks for a card on the free plan.
- Nothing else. There's no domain, server or database to look after.

## Per release

Do this when the release branch exists and its issues are merged. Replace `0-2-1` / `v0.2.1` with the new version.

### 1 · The branch's own `render.yaml`
On the new release branch, edit `render.yaml`:
- `name: rlm-api-v0-2-1`
- `branch: release/v0.2.1`

Commit that on the branch. Nothing else changes.

### 2 · API on Render
1. Render dashboard → **New → Blueprint** → pick this repository and the **release branch**. Render reads `render.yaml` and proposes one free web service. Apply it.
2. Wait for the first deploy to pass its health check (`/api/health`). The deploy log should show `Demo seed done`.
3. Copy the service URL, e.g. `https://rlm-api-v0-2-1.onrender.com`.
4. Check it from this machine: `src/contract-test.sh https://rlm-api-v0-2-1.onrender.com` should print `contract ok`. The contract test signs up its own throwaway accounts, and the next reset removes them.
5. Service → **Settings → Deploy Hook** → copy the URL. GitHub → repository **Settings → Secrets and variables → Actions → New secret** named `RENDER_HOOK_V0_2_1`.

`JWT_SECRET` is generated by Render per service, so it is never in the repo and differs between releases.

### 3 · Web on Vercel
1. Vercel dashboard → **Add New → Project** → import this repository.
2. Project name `rlm-v0-2-1`. Root directory `src/frontends/web`. Framework preset Next.js, detected automatically.
3. Environment variable `NEXT_PUBLIC_API_URL` = the Render URL from step 2.3, with no trailing slash. It is baked in at build time, so changing it later needs a redeploy.
4. Deploy. Then **Settings → Git → Production Branch** = `release/v0.2.1`, and **Settings → General → Node.js Version** = 22.x. Vercel no longer builds on 18, and Next.js 15 runs on 22. Redeploy once so both settings apply.
5. Open `https://rlm-v0-2-1.vercel.app` on a phone: sign in as the demo organizer, then open `/l/tuesdy` signed out.

### 4 · Nightly reset
Add the new secret's name to the `hook:` list in `.github/workflows/nightly-reset.yml` and keep the older ones. GitHub only runs scheduled workflows from `main`, so the new release is reset from the night its release branch merges to `main`. To reset now, use **Actions → Nightly demo reset → Run workflow**.

### 5 · README
Add the release's web URL to the "Try it" table in the root `README.md`. Leave the older rows in place.

## Older releases

Leave them alone. Each one is its own Render service and Vercel project, built from its own release branch. A later release never redeploys them, except for the nightly reset.

## When something goes wrong

| Symptom | Likely cause |
|---|---|
| Web says "Can't reach the backend at …" | `NEXT_PUBLIC_API_URL` is wrong or has a trailing slash. Fix it and redeploy the Vercel project. |
| First request hangs for about 50 s | That's normal: the free API was asleep. |
| Render deploy fails at start with `Seed refused at …` | A route refused the seed's data. The previous deploy keeps serving. Fix the seed on a dev branch. |
| Demo data didn't reset overnight | The secret is missing, which shows as a warning in the workflow run. Or GitHub paused scheduled workflows after 60 days without a commit: re-enable it under Actions. |
