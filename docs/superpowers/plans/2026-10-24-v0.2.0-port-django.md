# v0.2.0 Django Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `src/backends/django` serves the whole v0.2.0 contract, so `src/contract-test.sh http://localhost:8001` passes and the web frontend runs the PRD demo against Django.

**Architecture:** Django 5.2 + DRF, SQLite through the ORM with migrations. Sign-in uses Django's built-in `User` for accounts and password hashing, and `djangorestframework-simplejwt` for the access/refresh pair (ADR 004: "batteries included"). The pure logic (`round_robin`, `compute_standings`) is copied from FastAPI, not shared: the architecture doc deliberately keeps each backend self-contained (ADR 002), and the copies are kept honest by the contract test and by mirrored unit tests.

**Tech Stack:** Python 3.12, Django 5.2, DRF 3.18, djangorestframework-simplejwt 5.x, django-cors-headers, Django's test runner (`manage.py test`, `APITestCase`).

**Spec:** `docs/superpowers/specs/2026-10-24-v0.2.0-release-design.md`. **The contract** is the route table in `src/README.md` (every status, message and check order) plus `src/contract-test.sh`; **the reference implementation** is `src/backends/fastapi` — when the table is silent, do what FastAPI does.

## Global Constraints

- Every route, status, message, check order and JSON shape is exactly as in `src/README.md`. Messages word for word. Never a 422, never a 500 for bad input, never an HTML error page: every error is `{"error": "<message>"}`.
- No trailing-slash redirect: each route accepts both forms (`re_path(r"^…/?$")`, as the stub does).
- All ids in JSON are strings: model primary keys are `CharField(max_length=32, primary_key=True, default=uuid4().hex)`. The organizer's `User` id never appears in JSON.
- Emails are trimmed and lower-cased and stored as the `User.username` (and `email`). Passwords: **only** the 8-character minimum — do not run Django's `AUTH_PASSWORD_VALIDATORS` on signup (they refuse passwords FastAPI accepts, which would make backends disagree).
- Tokens: simplejwt with `ACCESS_TOKEN_LIFETIME` 1 hour, `REFRESH_TOKEN_LIFETIME` 30 days, `ROTATE_REFRESH_TOKENS = True` (refresh returns a new pair), `SIGNING_KEY` from env `JWT_SECRET` falling back to `SECRET_KEY`. Responses use the contract's names `{token, refresh_token}`, not simplejwt's `{access, refresh}`. An access token used as a refresh token, or vice versa, is refused.
- `DEFAULT_AUTHENTICATION_CLASSES` = simplejwt only (no session auth, so no CSRF on the API). Any authentication failure on a 🔒 route → `401 {"error": "Sign in required"}`.
- Body rule: on every route that takes a body, a body that isn't a JSON object (including missing or broken JSON) → `400 {"error": "Invalid request"}`, checked first.
- Lengths count Unicode code points (Python `len`), as FastAPI does. Names: 100 max; weeks 1–52; 52 entrants max. Scores: integers 0 ≤ n < 2³¹, `21.0` counts as 21, booleans refused.
- Leagues list oldest first (`created_at`, then `id`). Entrants list in the order added (`position`). Games by `week`, then `slot`.
- `round_robin` must produce **the same schedule as FastAPI's** for the same ordered entrant ids (copy it with its docstring). `compute_standings` likewise.
- Port 8001 (already the default via `api/management/commands/runserver.py`). Never commit `db.sqlite3` or `.venv`.
- Branches: `dev/<issue>-<slug>` off `release/v0.2.0`, merged back with `--no-ff` by the controller. Commit messages say what was decided.
- Product questions the contract doesn't settle: stop and ask the organizer (spec §4).

## Review Focus

1. **Django answering in its own format** — a DRF `ValidationError`, `NotAuthenticated`, `ParseError`, `NotFound` or `MethodNotAllowed` leaking DRF's `{"detail": …}` body instead of `{"error": …}`. One custom exception handler must map them all; a test per kind. (Task 1)
2. **simplejwt's shapes leaking** — `{access, refresh}` or simplejwt's own 401 body `{"detail": …, "code": "token_not_valid"}`. Expect the contract's names and `Sign in required`. (Task 1)
3. **Django's password validators** refusing `cornhole1`-style passwords that FastAPI accepts. Expect only the 8-character rule. (Task 1)
4. **`21.0` and `true`** — DRF's JSON parser gives a float and a bool; refuse the bool, accept the integral float. (Task 3)
5. **A different schedule from FastAPI's** for the same entrants — the web app and the public page look the same on either backend only if the pairs and home/away match. A test compares Django's `round_robin` output with a fixture generated from FastAPI's. (Task 3)
