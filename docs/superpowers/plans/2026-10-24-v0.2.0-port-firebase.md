# v0.2.0 Firebase Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the Firebase Emulator Suite in `src/backends/firebase` serves the whole v0.2.0 contract through its Cloud Function, so `src/contract-test.sh http://localhost:5000` passes and the web frontend runs the PRD demo against it.

**Architecture:** One HTTPS Cloud Function, `api` (Node 18, CommonJS, `firebase-functions` v6), split into small modules under `functions/`. Hosting rewrites `/api/**` to it. Sign-in is the Auth emulator's email/password, called through its REST endpoints (`accounts:signUp`, `accounts:signInWithPassword`, `securetoken` refresh) behind the contract's rules; ID tokens are verified with `firebase-admin` (ADR 004). Data is Firestore, accessed only through the Admin SDK inside the function, so **ownership is checked in code** (`organizerId === uid`) and `firestore.rules` denies every direct client read and write — the document-store contrast with Supabase's row-level security. **A league's schedule is one document** (`leagues/{id}/schedule/current`, an array of games), so generating, clearing and scoring are single-document transactions — a Firestore transaction can't hold the 1,300+ game writes a 52-entrant round robin would need as separate documents. `round_robin` and `compute_standings` are ported to JavaScript and pinned to FastAPI's output with the shared fixture.

**Tech Stack:** Firebase Emulator Suite (firebase-tools 13, Functions, Firestore, Auth, Hosting), Node 18, `firebase-admin` 12, `node:test` for unit tests (built in; no new test dependency).

**Spec:** `docs/superpowers/specs/2026-10-24-v0.2.0-release-design.md`. **The contract** is the route table in `src/README.md` plus `src/contract-test.sh`; **the reference** is `src/backends/fastapi` (Django and Supabase also conform).

## Global Constraints

- Every route, status, message, check order and JSON shape exactly as `src/README.md`, including the body rule (non-object body → `400 Invalid request`), the text rule (U+0000 or an unpaired surrogate in email/password/name/location/sport/season → `400 Invalid request`), unknown `/api/` path → `404 {"error": "Not Found"}`, wrong method on a known path → `405 {"error": "Method Not Allowed"}`, CORS everywhere. Never an Auth-emulator, Firestore or runtime error body; never a 500 for bad input.
- Routes that need no sign-in ignore any `Authorization` header.
- Ids are strings. Leagues and entrants use 32 lowercase hex ids generated by the function (`crypto.randomBytes(16).toString("hex")`); a game id is the league id, a per-schedule generation and the game's index joined (e.g. `<league>.<gen>.<n>`), so a score lookup finds its league without a query and regenerating changes every id. Any id that doesn't match the expected shape is simply not found (404) — never let it reach a Firestore path.
- Emails trimmed and lower-cased; passwords: 8 code points minimum, 72 UTF-8 bytes maximum, checked before the Auth emulator is called. Map the Auth emulator's `EMAIL_EXISTS` → 409, its bad-credential codes → `401 Email or password is incorrect`, any refresh failure → `401 Sign in required`.
- Lengths in code points (`[...s].length`); duplicates compared with `toLowerCase()` after trim; scores integers 0 ≤ n < 2³¹ (`21.0` and `3.0` count; booleans and strings don't).
- Orders: leagues oldest first (`createdAt`, then `id`); entrants by `position`; games by `week`, then `slot` (array order).
- `round_robin` gives FastAPI's schedule for the same ordered ids (fixture test). Standings computed in the function on every read; nothing stores them.
- Data survives emulator restarts: `npm run emulators` uses `--import=./emulator-data --export-on-exit`, with `emulator-data/` git-ignored (spec §6).
- Port 5000 (`API_URL`); stop the emulators when you finish. Branches `dev/<issue>-<slug>` off `release/v0.2.0`, merged by the controller. Product questions → stop and ask (spec §4).

## Review Focus

1. **Firebase's own error shapes leaking** — the Auth emulator's `{"error":{"code":400,"message":"EMAIL_EXISTS"}}`, a Firestore exception or a function crash page. (All tasks)
2. **An ownership check missing** — the Admin SDK bypasses `firestore.rules`, so every organizer route must compare `organizerId` with the token's `uid`; a test signs in as two organizers on every route. (Tasks 2–4)
3. **An id used as a Firestore path** — `/`, `..` or an empty segment in a league or game id must be a 404, not an exception. (Tasks 2–3)
4. **A different schedule from FastAPI's** — fixture test. (Task 3)
5. **Data lost on restart** — export/import really round-trips a league. (Task 4)
