# v0.2.0 Supabase Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the self-hosted Supabase stack in `src/backends/supabase` serves the whole v0.2.0 contract through its Edge Function, so `src/contract-test.sh http://localhost:54321/functions/v1` passes and the web frontend runs the PRD demo against it.

**Architecture:** One Edge Function, `docker/volumes/functions/api/` (Deno, TypeScript), split into small modules. Data lives in Postgres tables created by `migrations/*.sql`, with **row-level security**: the function talks to PostgREST with `npm:@supabase/supabase-js@2` using **the organizer's own access token**, so Postgres itself refuses another organizer's rows (ADR 003's "second line of defence" made real). The public page reads with the service-role key. Sign-in is Supabase Auth (GoTrue): the function validates the contract's rules, then calls GoTrue's signup/token endpoints and returns `{token, refresh_token}` (ADR 004). `round_robin` and `compute_standings` are ported to TypeScript and pinned to FastAPI's output with the same fixture Django uses.

**Tech Stack:** Supabase self-hosted (Edge Runtime 1.76 / Deno, Postgres 17, GoTrue 2.196, PostgREST 14), TypeScript, `supabase-js` 2, `deno test` for unit tests, run in the pinned `denoland/deno:2.1.4` Docker image so the host needs nothing but Docker (CLAUDE.md: Supabase is "Docker only").

**Spec:** `docs/superpowers/specs/2026-10-24-v0.2.0-release-design.md`. **The contract** is the route table in `src/README.md` plus `src/contract-test.sh`; **the reference** is `src/backends/fastapi` (Django is a second, already-conforming example).

## Global Constraints

- Every route, status, message, check order and JSON shape exactly as `src/README.md`. Every error is `{"error": "<message>"}` from our function — never a GoTrue, PostgREST or Edge Runtime body (`{"code":…,"msg":…}`, `{"message":…}`), and never a 500 for bad input.
- Paths: the function sees `/api/...` (the gateway strips `/functions/v1`); accept an optional trailing slash; unknown `/api/` path → `404 {"error": "Not Found"}`; wrong method on a known path → `405 {"error": "Method Not Allowed"}`. CORS on every response, including errors and `OPTIONS`.
- Routes that need no sign-in (health, backend, hello, signup, login, refresh, public) ignore any `Authorization` header. `FUNCTIONS_VERIFY_JWT` stays `false` (the gateway must not check tokens; our function does).
- Ids are strings: tables use `text` primary keys defaulting to `replace(gen_random_uuid()::text, '-', '')` (32 hex characters, like FastAPI's). A malformed id is simply not found (404), never a 500.
- Emails trimmed and lower-cased before GoTrue sees them; only the 8-character password rule (checked by us before GoTrue). `ENABLE_EMAIL_AUTOCONFIRM=true` (no mail server; spec §2). Access tokens last 1 hour (`JWT_EXPIRY=3600`); refresh returns a new pair.
- **Refresh tokens are single-use in GoTrue.** Clients must use the newest `refresh_token`; `src/README.md` says so, and `src/contract-test.sh` must never reuse one (Task 1 fixes the script).
- Lengths count Unicode code points (`[...s].length`). Lower-casing is `toLowerCase()`. Scores: integers 0 ≤ n < 2³¹ (`JSON.parse` already turns `21.0` into 21; booleans refused). `NaN`/`Infinity` aren't JSON, so they are `400 Invalid request`.
- Body rule: any route that takes a body answers `400 Invalid request` for a missing, broken or non-object body, checked first.
- Orders: leagues oldest first (`created_at`, then `id`); entrants by `position`; games by `week`, then `slot`.
- `round_robin` gives the same schedule as FastAPI's for the same ordered ids (fixture test). Standings are computed in the function on every read; nothing stores them.
- Schedule replacement (delete old games, insert new, update weeks) happens in **one transaction**: a Postgres function called with `rpc`.
- Never commit `docker/.env` or `docker/volumes/db/data`. Stop the stack when done (`cd docker && docker compose down`). Port 54321.
- Branches `dev/<issue>-<slug>` off `release/v0.2.0`, merged by the controller. Product questions → stop and ask (spec §4).

## Review Focus

1. **Supabase's own error bodies leaking** — a GoTrue `422 {"code":"user_already_exists",…}`, a PostgREST `{"message":…}` or the runtime's `{"code":"EDGE_FUNCTION_ERROR"}`. Expect the contract's status and message every time. (Tasks 1–4)
2. **Row-level security not actually on** — a policy missing, or the function quietly using the service key for organizer routes, so another organizer's league is readable or writable. A test signs in as two organizers and proves both the function's 404 and that PostgREST itself returns no rows for the other's token. (Task 2)
3. **A refresh token reused** — GoTrue revokes the whole session family on reuse detection; the web client always uses the newest token, the contract test must too. (Task 1)
4. **The schedule replaced half-way** — delete succeeded, insert failed. One transaction via `rpc`. (Task 3)
5. **A different schedule from FastAPI's** — the TS `round_robin` against the shared fixture. (Task 3)
