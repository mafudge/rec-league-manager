# v0.2.0 Reference Build (FastAPI + web) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The eight MVP stories (US13, US01–US07) working end to end on FastAPI + the Next.js web frontend, with the full REST contract written into `src/README.md` and checked by `src/contract-test.sh`.

**Architecture:** FastAPI gains SQLAlchemy models on SQLite, JWT auth and one router per story area; pure logic (round-robin, standings) stays in plain modules with unit tests. The web app gains client-side pages under the App Router that talk only to `API_URL` through one client (`app/api.ts`) that attaches the token and refreshes it once on a 401. Each story lands as one GitHub issue on a `dev/` branch off `release/v0.2.0`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.1, SQLite, PyJWT, bcrypt, pytest · Next.js 15.5, React 19.1, TypeScript, Vitest + Testing Library · `jq` for the contract test.

**Spec:** `docs/superpowers/specs/2026-10-24-v0.2.0-release-design.md` (requirements: `docs/backlog.md` US13, US01–US07, verbatim).

**This plan covers phase 1 only.** The 20 port issues (Django, Supabase, Firebase, Streamlit, Flutter) get their own plans once this contract is merged, because they copy what this plan fixes.

## Global Constraints

- Every acceptance criterion message is reproduced **word for word** in the backend's `{"error": ...}` and shown as-is by the frontend. Frontends never write their own validation messages.
- Errors are `{"error": "<message>"}` with a 4xx status. FastAPI must never answer 422: a `RequestValidationError` handler turns malformed bodies into `400 {"error": "Invalid request"}`.
- All ids in JSON are **strings** (Firestore can only do strings; every backend matches). FastAPI uses `uuid4().hex`.
- Emails are trimmed and lower-cased before storing or comparing. Entrant names are trimmed; duplicates are compared case-insensitively.
- Password minimum: 8 characters. Access token lifetime: 1 hour. Refresh token lifetime: 30 days.
- Slug: 6 characters from `abcdefghjkmnpqrstuvwxyz23456789`, generated with `secrets`, unique.
- Standings are computed on every request; no table stores them (PRD §5).
- Every screen works at 375 px wide with no horizontal scroll (PRD §5). Colors come from `docs/design/web-prototype.html` (`--ink #16342C`, `--paper #F4F0E4`, `--bag-blue #2E5FA3`, `--bag-gold #D9A431`, `--brick #A34430`, `--line #D8D2C0`, `--muted #5B6E67`).
- Branches: `dev/<issue>-<slug>` off `release/v0.2.0`, merged back with `--no-ff`. Commit messages say what was decided (CLAUDE.md).
- If building turns up a bug, gap or undecided choice: **stop and ask the organizer** whether it's fixed in v0.2.0 or goes on the backlog (spec §4).

### The contract (fixed by this plan; ports copy it)

All paths under `{API_URL}/api`. 🔒 = needs `Authorization: Bearer <token>`; missing, malformed or expired token → `401 {"error": "Sign in required"}`.

| Route | Body | Success | Errors (status, message) |
|---|---|---|---|
| `POST /auth/signup` | `{email, password}` | `201 {token, refresh_token}` | 400 `Enter a valid email address` (no `@`) · 400 `Password must be at least 8 characters` · 409 `An account with that email already exists` — checked in that order |
| `POST /auth/login` | `{email, password}` | `200 {token, refresh_token}` | 401 `Email or password is incorrect` (unknown email, wrong or missing password) |
| `POST /auth/refresh` | `{refresh_token}` | `200 {token, refresh_token}` | 401 `Sign in required` |
| 🔒 `GET /auth/me` | | `200 {email}` (the header shows who's signed in) | |
| 🔒 `GET /leagues` | | `200 [League]`, oldest first, only mine | |
| 🔒 `POST /leagues` | `{name, location, sport, season, weeks, allow_ties}` | `201 League` | 400 `Name is required` · 400 `Location is required` · 400 `Weeks must be at least 1` (missing, non-integer, < 1) — in that order |
| 🔒 `GET /leagues/{id}` | | `200 League` | 404 `League not found` (unknown or someone else's) |
| 🔒 `GET /leagues/{id}/entrants` | | `200 [Entrant]`, in the order added | 404 `League not found` |
| 🔒 `POST /leagues/{id}/entrants` | `{name}` | `201 Entrant` | 400 `Name is required` · 409 `An entrant with that name already exists in this league` · 404 |
| 🔒 `POST /leagues/{id}/schedule` | | `201 {weeks, message}` | 400 `Add at least 2 entrants first` · 409 `Scores already recorded — clear them first` · 404 |
| 🔒 `GET /leagues/{id}/games` | | `200 [Game]` by week, then by position in the week | 404 |
| 🔒 `DELETE /leagues/{id}/scores` | | `200 {cleared: <n games>}` | 404 |
| 🔒 `PUT /games/{id}/score` | `{home_score, away_score}` | `200 Game` | 400 `Scores must be whole numbers 0 or greater` · 400 `A bye has no score` · 400 `This league doesn't allow ties` · 404 `Game not found` (unknown or someone else's) |
| 🔒 `GET /leagues/{id}/standings` | | `200 Standings` | 404 |
| `GET /public/{slug}` | | `200 {league: PublicLeague, current_week, games: [Game], standings: Standings}` | 404 `League not found` |

Shapes:
- `League` = `{id, slug, name, location, sport, season, weeks, allow_ties}`. `sport` and `season` may be empty strings. `allow_ties` defaults to `false` when absent.
- `PublicLeague` = `League` without `id`.
- `Entrant` = `{id, name}`.
- `Game` = `{id, week, home_id, home_name, away_id, away_name, home_score, away_score}`; a bye has `away_id`/`away_name`/scores `null`.
- `Standings` = `{rows: [{entrant_id, name, w, l, t, pf, pa, diff}], played: <games with a score>, tiebreak: "Sorted by wins, then point difference, then points for."}`. `t` is always present; frontends hide the column when `allow_ties` is false.
- Schedule `message` is `null` when weeks didn't change, else exactly `This schedule needs {n} weeks, so the league now runs {n} weeks instead of {old}.`
- `current_week` = lowest week with an unplayed non-bye game; if all are played, the last week; `null` when there's no schedule.

## Review Focus

1. **A score typed on a bye game** — the organizer taps a bye row. Expect `400 A bye has no score`; the web schedule shows no score fields on a bye. Pinned in Task 6.
2. **Same name or email typed differently** — `" bag ladies "` after `"Bag Ladies"`, or `Mike@X.com` after `mike@x.com`. Expect the duplicate refusal, not a second row/account. Pinned in Tasks 2 and 4.
3. **Scores that aren't whole numbers** — `21.5`, `"21"`, `true`, `null`. Expect `400 Scores must be whole numbers 0 or greater`, never a 500 or a stored value. Pinned in Task 6.
4. **Another organizer's game id** — `PUT /games/{id}/score` with a game from someone else's league. Expect `404 Game not found`; ownership is checked through the game's league, not just on `/leagues/{id}`. Pinned in Task 6.
5. **The access token expires mid-evening** — the next request gets 401. Expect the web client to refresh once and retry without the organizer noticing; only a failed refresh sends them to sign in. Pinned in Task 3.
