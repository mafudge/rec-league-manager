## v0.2.0 MVP

- **US06 (calculation)** FastAPI computes standings from games — #14. `app/standings.py` `compute_standings(entrants, games)`: W, L, PF, PA, Diff; sorted W → Diff → PF (then name); byes and unplayed games contribute nothing. One test per AC, 14/14 pass. The endpoint, the page (tiebreak text, "No games played yet") and the other three backends are still to do.
- **US13** Organizer signs up — #17. FastAPI: SQLite via SQLAlchemy, one `{"error"}` shape (never 422), bcrypt + JWT pair (1 h access, 30 d refresh), `POST /api/auth/signup` with emails trimmed and lower-cased and a signup race answered 409. Web: `/signup`, tokens in `localStorage`. `contract-test.sh` now needs `jq` and checks signup. pytest 25 passed, web 16 passed, contract ok.
- **US01** Organizer signs in — #18. `POST /api/auth/login` (one refusal for unknown email or wrong password), `/auth/refresh`, `GET /api/auth/me` and a `current_organizer` gate (401 "Sign in required"). Web: `/signin`, refresh once on 401 and retry, sign-in redirect, header with Sign out; server errors now say "The backend had a problem (n)". pytest 32, web 34 passed, contract ok.
- **US02** Create a league — #19. `POST/GET /api/leagues` and `GET /api/leagues/{id}`: only my leagues, oldest first; 6-character random slug; "Games can end in a tie" (off by default); another organizer's league is 404. Web: league list with its empty state, create form, league home with Copy public link. pytest 63, web 46 passed, contract ok.
- **US03** Add entrants — #20. `GET/POST /api/leagues/{id}/entrants`: in the order added; duplicates refused after trimming, ignoring case. Web: Entrants · Schedule · Standings tabs; name + Add on one row, no horizontal scroll at 375 px (checked live). Contract test also pins `allow_ties` and `weeks: true` refusals. pytest 80, web 54 passed, contract ok.
- **US04** Generate a round-robin schedule — #21. Circle method in `app/schedule.py`: n−1 weeks for even n, n for odd n, each entrant byes exactly once. `POST /schedule` replaces when no scores, refuses with scores, and sets the league's weeks to match with a message; `GET /games`; `DELETE /scores` ("Clear all scores", behind a confirmation in the web app). pytest 95, web 61 passed, contract ok.
- **US05** Record a score — #22. `PUT /api/games/{id}/score`: replaces, refuses negatives, blanks, fractions, booleans and huge numbers (`21.0` counts as 21 so the JS backends agree), refuses byes ("A bye has no score") and ties in leagues without them; another organizer's game is 404. Web: score inputs per game, saved rows stay editable. Contract test pins byes and `21.0`. pytest 116, web 65 passed, contract ok.
- **US06** Standings compute themselves — #23, with **US06-01** (#15). `GET /api/leagues/{id}/standings`: W, L, T, PF, PA, Diff computed on every request, sorted W → Diff → PF then name, with the tiebreak sentence and a `played` count; bad game data raises a clear `ValueError`. Web: standings table (T only in leagues that allow ties), "No games played yet", fits 375 px. pytest 124, web 72 passed, contract ok.
- **US07** Public link to schedule and standings — #24. `GET /api/public/{slug}` (no sign-in, no `id`, `current_week`); web `/l/{slug}` shows this week first, then the full schedule, then standings, with nothing that writes, and "League not found" for a bad link. **Phase-1 demo passed on FastAPI + web**, driven through the UI in headless Chrome at 375 px: sign up, create "Tuesday Cornhole", add 6 teams, generate (weeks 8 → 5 with the message), score week 1, open the public link (this week's games end at 301 of 667 px, no horizontal scroll). pytest 130, web 80 passed, `npm run build` ok, contract ok.
